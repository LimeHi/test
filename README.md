# VPN Subscription Checker Bot

Telegram-бот: юзер присылает подписку (ссылка / .txt / base64), бот вытаскивает
конфиги (vless/vmess/trojan/ss/ssr, максимум `MAX_CONFIGS`), ставит задачу в
очередь и проверяет каждый сервер в несколько уровней.

## Уровни проверки

1. **TCP-коннект** (`checker.tcp_check`) — базовая доступность порта. Быстро,
   но может врать: DPI/файрвол иногда отвечает на SYN вместо реального сервера,
   либо порт открыт, а сервис за ним не поднят.
2. **TLS-хендшейк** (`checker.tls_check`) — для конфигов с `security=tls|reality`.
   Ловит случаи "порт открыт, но нормального TLS там нет".
3. **ICMP ping** — чисто информационно, в вердикт "жив/мёртв" НЕ входит, потому
   что провайдер часто режет ICMP независимо от реальной работоспособности VPN.
4. **Deep-check через xray-core** (`xray_manager.deep_check`) — опционально
   (`ENABLE_DEEP_CHECK=1`). Поднимает локальный `xray-core` процесс с конфигом
   именно этого сервера (SOCKS5-инбаунд), и делает настоящий HTTP GET на
   `CHECK_URL` через него. Это единственный уровень, который реально ловит
   DPI-блокировку протокола/SNI после хендшейка — TCP и TLS её не видят.
   Если `DEEP_CHECK_AUTHORITATIVE=1` (по умолчанию), то когда deep-check
   реально смог выполниться, именно его результат становится финальным
   вердиктом "жив/мёртв".

## Свой текст / флаг в именах

После того как бот нашёл конфиги, он спросит, добавить ли свой текст к именам
(`/skip`, чтобы не добавлять). Флаг страны (emoji regional indicator, если он
был в оригинальном имени) сохраняется в любом случае — рендерится модулем `flags.py`.
В `working_configs.txt` имена конфигов уже с флагом + вашим текстом.

## Установка xray-core (для deep-check)

Deep-check не обязателен — без него бот прекрасно работает на TCP/TLS/ICMP.
Если нужен:

```bash
mkdir -p bin
curl -L -o /tmp/xray.zip \
  https://github.com/XTLS/Xray-core/releases/latest/download/Xray-linux-64.zip
unzip /tmp/xray.zip -d bin/
chmod +x bin/xray
```

Проверить, что бинарь рабочий: `./bin/xray version`.

`XRAY_BIN` в `.env` должен указывать на этот путь.

**Важно про хостинг**: deep-check спавнит отдельный процесс `xray-core` на
каждую проверку (с лимитом `DEEP_CHECK_CONCURRENCY`, по умолчанию 8
одновременно). На слабых/шаренных тарифах (типа минимальных планов
BotHost/Railway) это может упереться в CPU/RAM лимиты — начните с
`DEEP_CHECK_CONCURRENCY=3-5` и смотрите на потребление.

## Известные ограничения конвертера (config_converter.py)

Конвертация share-ссылок в JSON для xray-core покрывает основные кейсы
(VLESS+Reality/TLS+tcp/ws/grpc/xhttp, Trojan+TLS, VMess+TLS/ws, Shadowsocks).
Экзотические/нестандартные параметры отдельных панелей могут не совпасть один
в один — если `to_outbound()` не смог собрать валидный конфиг (или xray не
поднялся с ним), deep-check для этого сервера просто помечается как
`DEEP:skip(...)`, а вердикт откатывается на TCP/TLS. Рекомендую прогнать на
своих реальных VLESS+Reality+XHTTP конфигах и подправить `_stream_settings`
под конкретные параметры панели, если что-то не заведётся с первого раза.

## Запуск

```bash
pip install -r requirements.txt

```
